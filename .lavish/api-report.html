1Module Architecture

Each domain module registers only the Mongoose models it needs — there is no shared "models" module. CompanyModule imports AuthModule purely for the guard, and CertificateModule for certificate issuance. Two modules reach out to the external ICID service.

2External Integration Points

Only company.service.ts and certificate.service.ts make outbound HTTP calls — both via raw axios, both against process.env.ICID_SERVICE_BACKEND_URL. ICID is a separate open-source service (not bundled in this repo) that mints company IDs and issues/verifies Hedera-anchored certificates. No other module talks to an external service.

Caller Verb External URL Purpose
CompanyService.createCompany POST {ICID_SERVICE_BACKEND_URL}/company Mints a new company IFRIC URN id from dataspace/object/region/country codes; the returned urn_id becomes company_ifric_id.
CompanyService.createCompany rollback DELETE {ICID_SERVICE_BACKEND_URL}/company/:temp_icid_company_id Compensating action if local company creation fails after the ID was already minted — a saga-style rollback so ICID and Mongo don't drift out of sync.
CertificateService.generateCompanyCertificate POST {ICID_SERVICE_BACKEND_URL}/certificate/create-company-certificate Mints a certificate/DID/Hedera key pair for a company; the private key is AES-256-CBC encrypted locally (keyed by HEDERA_KEY_SECRET) before being stored.
CertificateService.verifyCompanyCertificate POST {ICID_SERVICE_BACKEND_URL}/certificate/verify-company-certificate Checks whether one company's Hedera-anchored certificate is revoked.
CertificateService.verifyAllCompanyCertificate POST {ICID_SERVICE_BACKEND_URL}/certificate/verify-all-company-certificate Batch verification (50 at a time); called internally by CompanyService.getAllCompanies() to annotate GET /company/get-all-companies results with a live company_cert flag.

4Auth Model & Security Notes

Token model

  • access_token 1 hour
    Stateless. AuthGuard checks signature + type claim only — no DB round trip. Stays valid for its full lifetime even after logout.
  • refresh_token 30 days
    Stored server-side on CompanyUser.jwt_token. Exchanged via POST /auth/refresh. /auth/logout clears it — the only point where revocation is actually enforced.

A token minted for one purpose (type: 'access' vs 'refresh') is rejected if used for the other. Passwords are bcrypt-hashed, never stored or returned in reversible form.
